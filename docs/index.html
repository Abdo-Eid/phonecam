Use your Android phone as a webcam on Windows. استخدم هاتف أندرويد ككاميرا ويب على ويندوز.

PhoneCam is an open-source Android app plus a Windows program. Together they register a real virtual camera, so Zoom, Chrome, OBS and Windows Camera all see the phone as a normal webcam. It works today, but it is not finished. This page is for people who want to help build it. ‏PhoneCam تطبيق أندرويد مفتوح المصدر مع برنامج على ويندوز. معًا يسجّلان كاميرا افتراضية حقيقية، فترى تطبيقات Zoom و Chrome و OBS وكاميرا ويندوز الهاتفَ ككاميرا ويب عادية. يعمل المشروع اليوم لكنه غير مكتمل، وهذه الصفحة لمن يريد المساعدة في تطويره.

Status: the whole pipeline works on real hardware and has been tested. There is no installer and no release yet, so for now you build it from source. This page says plainly what is done and what is not. الحالة: المسار كامل يعمل على عتاد حقيقي وجرى اختباره. لا يوجد مُثبِّت ولا إصدار جاهز بعد، لذا تبنيه حاليًا من المصدر. تذكر هذه الصفحة بوضوح ما أُنجز وما لم يُنجز.

Pipelineالمسار

How it worksكيف يعمل

Video passes through six stages in order, from the phone's camera to the virtual camera Windows shows to apps. يمرّ الفيديو عبر ست مراحل بالترتيب، من كاميرا الهاتف إلى الكاميرا الافتراضية التي يعرضها ويندوز للتطبيقات.

01

Captureالتقاط

Camera2 binds straight to MediaCodec's input Surface. Hardware H.264, no pixel copies on the phone.تُربط Camera2 مباشرةً بـ input Surface الخاص بـ MediaCodec. ترميز H.264 بالعتاد، دون أي نسخ للبكسلات على الهاتف.

02

Frameتأطير

A fixed 20-byte header per video packet; FlatBuffers envelopes carry commands and telemetry on a second channel.ترويسة ثابتة من 20 بايت لكل حزمة فيديو، بينما تحمل رسائل FlatBuffers الأوامر والقياسات على قناة ثانية.

03

Transportالنقل

USB tethering, ADB, or AOA — detected automatically in that order, no setting to choose.‏USB tethering أو ADB أو AOA — يُكتشف تلقائيًا بهذا الترتيب، دون أي إعداد يختاره المستخدم.

04

Decodeفكّ الترميز

Media Foundation decodes H.264 into NV12 frames on the PC, hardware-accelerated where available.تفكّ Media Foundation ترميز H.264 إلى إطارات NV12 على الحاسوب، بتسريع عتادي حيثما توفّر.

05

Handoffالتسليم

A shared-memory ring crosses the process and session boundary into Windows' Frame Server, which runs as a service.‏ring buffer في ذاكرة مشتركة يصل بين العمليتين إلى Frame Server في ويندوز، وهو يعمل كخدمة.

06

Cameraالكاميرا

MFCreateVirtualCamera registers a source Windows serves to Media Foundation and DirectShow apps alike.يسجّل MFCreateVirtualCamera مصدرًا يقدّمه ويندوز لتطبيقات Media Foundation و DirectShow على حدّ سواء.

Stage 03المرحلة 03

The three transportsقنوات النقل الثلاث

Getting video off an Android phone over USB without root is the hardest part of the project. Three transports exist, and the Windows program picks one automatically at startup. إخراج الفيديو من هاتف أندرويد عبر USB دون صلاحيات root هو أصعب جزء في المشروع. توجد ثلاث قنوات نقل، ويختار برنامج ويندوز إحداها تلقائيًا عند بدء التشغيل.

Recommendedموصى به

USB tetheringUSB tethering

Turn on USB tethering on the phone. It presents a network interface, Windows loads its own built-in driver, and the connection becomes a normal TCP socket carrying both video and camera controls. فعّل USB tethering في الهاتف. سيقدّم واجهة شبكة، ويحمّل ويندوز تعريفه المدمج، ويصبح الاتصال مجرد TCP socket عادي يحمل الفيديو وأوامر التحكم بالكاميرا معًا.

Original pathالمسار الأصلي

ADBADB

Forwards a port over the Android Debug Bridge. Reliable and well tested, but the user has to turn on Developer Options first. That is the step the other two transports avoid. يمرّر منفذًا عبر Android Debug Bridge. موثوق ومُختبر جيدًا، لكن على المستخدم تفعيل خيارات المطوّر أولًا. وهذه هي الخطوة التي تتفاداها القناتان الأخريان.

  • Driver to installتعريف يُثبَّتNoneلا شيء
  • Developer Optionsخيارات المطوّرRequiredمطلوبة

  • Camera controlsالتحكم بالكاميراYesنعم

Fallbackاحتياطي

AOAAOA

Android Open Accessory mode. Also needs no Developer Options, but Windows has no built-in driver for raw USB access, so one has to be installed. That stops file transfer working until it is removed again. وضع Android Open Accessory. لا يحتاج خيارات المطوّر أيضًا، لكن ويندوز لا يملك تعريفًا مدمجًا يتيح الوصول المباشر إلى USB، فيلزم تثبيت واحد. وهذا يوقف نقل الملفات حتى تتم إزالته.

  • Driver to installتعريف يُثبَّتYes, one promptنعم، بموافقة واحدة
  • Developer Optionsخيارات المطوّرNot neededغير مطلوبة
  • Latencyزمن الاستجابةUSB
  • Camera controlsالتحكم بالكاميراNo — video onlyلا — فيديو فقط
  • DisplacesيُعطّلFile transferنقل الملفات

USB tethering is not wireless. It is a USB cable carrying a network protocol, which is why it has USB latency but needs no driver. It replaced AOA as the recommended transport. ‏USB tethering ليس اتصالًا لاسلكيًا. هو كابل USB يحمل بروتوكول شبكة، ولذلك يعطي زمن استجابة USB دون الحاجة إلى أي تعريف. وقد حلّ محلّ AOA كقناة النقل الموصى بها.

Orientationخريطة المشروع

Repository layoutهيكل المستودع

Two languages and three build systems. The Windows and Android sides share no code, only the wire format in proto/. لغتان وثلاثة أنظمة بناء. لا يتشارك جانبا ويندوز وأندرويد أي شيفرة، بل صيغة النقل في proto/ فقط.

android/
Kotlin. Camera2 capture, MediaCodec encode, the transports, and the on-phone UI.بلغة Kotlin. التقاط عبر Camera2، وترميز عبر MediaCodec، وقنوات النقل، وواجهة الهاتف.
windows/host/
C++. phonecam-host.exe — transports, H.264 decode, the tray UI and its controls.بلغة C++. ملف phonecam-host.exe — قنوات النقل، وفكّ ترميز H.264، وواجهة شريط المهام وأدواتها.
windows/vcam/
C++/COM. The MFCreateVirtualCamera media source Windows loads into its own Frame Server.بلغة C++/COM. مصدر الوسائط MFCreateVirtualCamera الذي يُحمّله ويندوز داخل Frame Server.
windows/common/
Shared C++: the cross-process frame ring, wire framing, logging.شيفرة C++ مشتركة: ring buffer الإطارات بين العمليات، وتأطير البيانات، والتسجيل.
windows/usbdriver/
The elevated helper that installs and removes the AOA driver. Only used by the fallback transport.أداة مساعدة تعمل بصلاحيات المدير، تثبّت تعريف AOA وتزيله. تُستخدم فقط مع القناة الاحتياطية.
proto/
FlatBuffers schemas — the contract both sides compile against. Change here, change both sides.مخططات FlatBuffers — العقد الذي يُبنى عليه الجانبان. أي تغيير هنا يستلزم تعديل الطرفين.

Portrait breaks in DirectShow appsالوضع الرأسي يتعطّل في تطبيقات DirectShow

The vertical resolutions look correct in Media Foundation apps but come out corrupted in DirectShow apps, which includes Zoom's classic client and older OBS. The cause is a byte-alignment bug in a Windows component, not in this code. Needs a workaround.تبدو الدقّات الرأسية صحيحة في تطبيقات Media Foundation لكنها تخرج تالفة في تطبيقات DirectShow، ومنها نسخة Zoom التقليدية وإصدارات OBS القديمة. السبب خلل في محاذاة البايتات داخل مكوّن من ويندوز، لا في هذه الشيفرة. تحتاج إلى حلّ التفافي.

HardصعبWindowsC++

The AOA connection can wedge silentlyاتصال AOA قد يتعلّق بصمت

After a replug, the USB read loop can time out forever without ever reporting the device is gone, so the reconnect logic never fires and the process needs a manual restart. A consecutive-timeout threshold would likely fix it.بعد إعادة توصيل الكابل، قد تستمر حلقة القراءة عبر USB في انتهاء المهلة إلى الأبد دون الإبلاغ عن اختفاء الجهاز، فلا تعمل آلية إعادة الاتصال ويحتاج البرنامج إلى إعادة تشغيل يدوية. غالبًا يكفي حدّ أقصى لعدد المهلات المتتالية.

The installer is incompleteالمُثبِّت غير مكتمل

No audioلا يوجد صوت

Video only, for now. Synced audio over the same cable is a stated goal and nothing has been built for it. The wire protocol has no audio channel, so this is a design task before it is a coding one.فيديو فقط حاليًا. نقل صوت متزامن عبر الكابل نفسه هدف معلن ولم يُبنَ منه شيء. لا يحتوي بروتوكول النقل على قناة صوت، لذا فهي مهمة تصميم قبل أن تكون مهمة برمجة.

Getting startedالبداية

Building from sourceالبناء من المصدر

You will needما تحتاجه

Visual Studio 2022 Build Tools with the C++ workload, the Windows 11 SDK, CMake, flatc and adb on PATH, plus JDK 21 and the Android SDK for the phone side. Full detail in docs/build.md. أدوات بناء Visual Studio 2022 مع حزمة C++، وحزمة Windows 11 SDK، و CMake، ووجود flatc و adb في PATH، إضافةً إلى JDK 21 وحزمة Android SDK لجانب الهاتف. التفاصيل كاملة في docs/build.md.

Thenثم

git clone https://github.com/Abdo-Eid/phonecam
cd phonecam
git submodule update --init --recursive

# Windows host
cmake --build windows/build --target phonecam-host --config Debug

# Android app
cd android && ./gradlew assembleDebug

The virtual camera builds with MSBuild rather than CMake, and has to be registered once. Both that and the deployment step people usually miss are explained in docs/build.md. تُبنى الكاميرا الافتراضية عبر MSBuild لا CMake، ويجب تسجيلها مرة واحدة. كلاهما وخطوة النشر التي يغفل عنها معظم الناس مشروحان في docs/build.md.
